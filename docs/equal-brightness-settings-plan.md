# 等亮度设置功能优化方案

> 状态：第一步已完成。通用设置中的“同步苹果和内置显示器的亮度设置”同一行已经加入“等亮度设置”按钮，按钮沿用“重置设置”的圆角推按钮样式，并补充了英文与简体中文标题。
>
> 本文规划后续的弹窗、人工参考点、曲线拟合、配置保存和自动同步接入。当前改动只改变入口界面，不改变已有亮度同步算法，便于逐阶段验证。

## 1. 需求定义

### 1.1 用户目标

用户希望把 Mac 内置屏幕或 Apple 显示器作为视觉参考。当用户调节参考屏幕亮度时，外接显示器不再简单复制相同的数值变化，而是按照每台显示器自己的亮度曲线变化，使多块屏幕在主观观感上尽量保持一致。

理想关系可以写成：

```text
Mac 参考亮度 x（0 到 1）  ->  外接显示器亮度 y（0 到 1）
y = f_display(x)
```

Mac 自己的参考曲线固定为正比例函数：

```text
f_mac(x) = x
```

其他显示器第一次使用时也使用正比例函数作为默认值：

```text
f_external(x) = x
```

用户通过实际观察调整参考点后，系统再为每台显示器建立独立的 `f_external`。

### 1.2 本次直接完成的范围

- 在“同步苹果和内置显示器的亮度设置”这一行增加“等亮度设置”按钮。
- 按钮使用和“重置设置”一致的圆角、边框、系统字体和系统控件颜色。
- 简体中文显示“等亮度设置”，英文显示“Equal Brightness Settings”。
- 不改动现有 `enableBrightnessSync` 开关的行为。
- 不在这一阶段把尚未验证的曲线算法接入实时同步循环。

### 1.3 后续功能范围

- 点击按钮后打开一个独立的设置窗口或设置 sheet。
- 在窗口中显示亮度坐标网格和多条曲线。
- Mac 参考曲线使用固定颜色和直线表示。
- 每台其他显示器使用稳定、可区分的颜色；默认曲线同样是直线。
- 允许用户添加、编辑、删除参考点。
- 用户可以通过滑块调节两台或多台显示器，直到肉眼判断亮度相等。
- 根据参考点选择合适的拟合函数。
- 保存、取消、预览、恢复默认和配置迁移都可控且可回滚。
- 将曲线映射接入当前的亮度同步流程，同时保留旧的线性增量同步作为兼容模式。

### 1.4 不在首版解决的问题

- 不使用摄像头、光度计或色度计自动测量真实物理亮度。
- 不承诺跨面板、跨色域、跨 HDR 状态的绝对亮度一致。
- 不替换现有 DDC、DisplayServices、Gamma 或 shade 控制实现。
- 不改变现有显示器识别、睡眠恢复和启动读取策略。
- 不用高阶多项式追求数学上更贴合但肉眼不稳定的曲线。

## 2. 现有代码与接入边界

### 2.1 当前设置入口

- `MonitorControl/View Controllers/Preferences/MainPrefsViewController.swift`
  - `enableBrightnessSync` 读取和写入 `PrefKey.enableBrightnessSync`。
  - 当前按钮只负责打开/关闭“同步亮度变化”开关。
- `MonitorControl/UI/Base.lproj/Main.storyboard`
  - “通用”设置页使用 `NSGridView`。
  - 新按钮和同步复选框放在同一个 grid cell 的水平 stack 中。
- `MonitorControl/UI/zh-Hans.lproj/Main.strings`
  - 提供“等亮度设置”中文标题。
- `MonitorControl/UI/en.lproj/Main.strings`
  - 提供英文标题，其他语言没有翻译时使用 Base storyboard 的英文回退。

### 2.2 当前实时同步流程

`MonitorControl/Support/AppDelegate.swift` 中的 `job()` 会周期性执行：

1. 遍历 `DisplayManager.shared.displays`。
2. 调用每台显示器的 `refreshBrightness()`。
3. 某台显示器发生变化时，得到一个 `delta`。
4. 如果 `PrefKey.enableBrightnessSync` 为真，对其他显示器执行：

```text
targetValue = clamp(targetDisplay.getBrightness() + delta, 0, 1)
targetDisplay.setBrightness(targetValue)
```

5. 同步更新目标显示器的菜单滑块。

这种方式假设所有显示器的“控制值变化”和“视觉亮度变化”近似相同。等亮度功能需要在目标显示器上使用绝对映射值，而不是直接复制同一个数值增量。

### 2.3 当前亮度抽象

- `Display` 使用 `0...1` 的归一化亮度值。
- `AppleDisplay` 通过 `DisplayServices` 读取和写入 Apple 显示器亮度。
- `OtherDisplay` 通过 DDC 或软件亮度控制外接显示器。
- `Display.setBrightness()` 会根据设置选择平滑过渡或直接设置。
- `Display.setDirectBrightness(_:transient:)` 可以在预览阶段设置临时值而不立即保存为用户亮度偏好。
- `brightnessSyncSourceValue` 用于判断外部亮度变化，需要避免曲线同步产生反馈循环。
- DDC 的最小值、最大值、组合硬件/软件调光和 Gamma 处理会影响外接显示器内部值，因此曲线必须作用于 MonitorControl 已经归一化的亮度值，不直接使用原始 DDC 数值。

### 2.4 接入原则

1. 先保留现有同步路径，曲线功能使用独立的开关或配置状态启用。
2. 只有配置有效且用户启用等亮度映射时，才使用曲线结果。
3. 配置无效、显示器身份变化、曲线计算失败时回退到现有线性增量同步。
4. 不在 `Touch`、DDC 或 DisplayServices 底层实现中重复增加曲线逻辑；曲线应放在同步层。
5. 预览值、已保存值和运行时目标值必须分开，取消时能完整恢复。

## 3. 用户界面规划

### 3.1 设置入口

位置：通用设置中现有“同步苹果和内置显示器的亮度设置”复选框右侧。

按钮行为：

- 显示器数量小于两台时仍可打开，但窗口显示“至少需要两台可控显示器”。
- 没有检测到 Mac 内置或 Apple 参考显示器时，窗口显示参考显示器不可用，并允许查看已有配置。
- 现有同步复选框关闭时，按钮仍可进入配置；保存的曲线不会被删除。
- 运行时是否应用曲线由“启用亮度同步”和新的“应用等亮度曲线”共同决定。首版可以把新开关放在弹窗内，默认关闭，避免升级后改变用户已有行为。

### 3.2 弹窗结构

建议使用独立的 `NSWindowController` 加 `NSViewController`，窗口初始大小约 `760 x 560`，支持调整大小。

```text
┌──────────────────────────────────────────────────────────┐
│ 等亮度设置                                               │
│ 参考显示器：MacBook 内置显示器       [启用等亮度曲线]    │
├───────────────────────────────┬──────────────────────────┤
│                               │ 显示器曲线               │
│       亮度曲线网格            │ [Mac 内置显示器] ✓参考   │
│       y 目标亮度              │ [外接显示器 A] 颜色块    │
│       1.0 ─────────           │ 拟合函数：[分段线性 ▾]   │
│           ╱                   │ [添加参考点]             │
│          ╱                    │ 参考点列表               │
│       0.0 ───────── x         │ 20% -> 24%  [编辑][删除]  │
│          0.0       1.0        │ 60% -> 68%  [编辑][删除]  │
├───────────────────────────────┴──────────────────────────┤
│ [恢复当前显示器默认曲线]       [取消] [保存]              │
└──────────────────────────────────────────────────────────┘
```

### 3.3 曲线图

- 横轴：Mac 参考显示器的归一化亮度 `x`，显示 0%、25%、50%、75%、100%。
- 纵轴：当前目标显示器的归一化亮度 `y`，显示 0%、25%、50%、75%、100%。
- 网格使用系统浅色/深色外观自动适配。
- `y=x` 的参考线用固定灰色或蓝色虚线表示，标签为“Mac 参考线”。
- 当前选中的外接显示器曲线用高亮实线显示，其他显示器使用较低透明度。
- 每条曲线颜色按显示器身份稳定生成，不能因为窗口重新打开而随机改变。
- 鼠标悬停时显示 `(x, y)` 百分比和当前拟合函数。
- 参考点使用同色圆点，选中时增加描边，不用过小的点击区域。
- 曲线必须被裁剪在 `0...1` 范围，不能绘制到坐标网格外。

### 3.4 显示器列表

每台显示器显示：

- 用户友好名称。
- 类型：Mac 内置、Apple 显示器、DDC 外接、软件控制、虚拟显示器。
- 当前亮度值。
- 是否为参考显示器。
- 是否存在有效曲线。
- 曲线颜色样本。

规则：

- Mac 内置或 Apple 显示器优先作为默认参考显示器。
- 参考显示器不能删除曲线，只能保持 `y=x`。
- 外接显示器可以选择“使用默认线性曲线”或自定义曲线。
- 显示器拔出后保留配置，重新插入并匹配身份后恢复。

### 3.5 添加参考点流程

点击“添加参考点”后：

1. 用户选择目标显示器；默认选中当前曲线显示器。
2. 窗口进入“校准预览”状态，保存原始亮度值。
3. 显示两个控制区：
   - Mac 参考亮度滑块 `x`。
   - 目标显示器亮度滑块 `y`。
4. 用户可以拖动任一滑块，并观察两块屏幕；也可以使用键盘左右方向键做小步进。
5. 用户认为两块屏幕在当前画面上亮度相等时，点击“记录参考点”。
6. 系统保存一对归一化值 `(x, y)`，并把点绘制到图上。
7. 允许继续添加其他亮度区间的点。
8. 点击“结束校准”后恢复预览前亮度，除非用户点击保存。

首版建议至少记录三个区域：

- 低亮度：约 10% 到 25%。
- 中亮度：约 40% 到 60%。
- 高亮度：约 75% 到 90%。

界面应提示用户保持相同的显示内容、视角和环境光；这只是主观校准，不能把“视觉相等”当成物理测量值。

### 3.6 参考点编辑

每个点显示：

- 参考亮度 `x`。
- 目标亮度 `y`。
- 添加时间。
- 可选备注，例如“夜间办公”“白色网页”“暗色编辑器”。

支持：

- 点击列表项定位图上点。
- 拖动图上点微调数值。
- 数值输入框精确修改。
- 删除单点。
- 删除全部点并恢复默认直线。
- 按 `x` 排序显示，不允许同一曲线出现相同 `x` 的重复点。

## 4. 数据模型

### 4.1 稳定显示器身份

不能只使用 `CGDirectDisplayID` 作为配置键，因为显示器重启、拔插或排列变化后这个 ID 可能变化。

建议建立：

```swift
struct DisplayIdentity: Codable, Hashable {
    let kind: DisplayKind              // builtIn, apple, external, virtual
    let vendorID: UInt32?
    let modelID: UInt32?
    let serialNumber: UInt32?
    let edidHash: String?
    let fallbackName: String
}
```

匹配优先级：

1. vendor + model + serial。
2. vendor + model + EDID hash。
3. 稳定的内置显示器标识。
4. 最后才使用名称作为人工确认的回退。

`CGDirectDisplayID` 只用于当前运行时查找，不直接作为长期保存键。

### 4.2 曲线配置

建议使用版本化 Codable 数据：

```swift
struct BrightnessMappingProfile: Codable {
    let schemaVersion: Int
    var referenceDisplay: DisplayIdentity
    var displays: [DisplayIdentity: BrightnessCurve]
    var isEnabled: Bool
    var updatedAt: Date
}
```

曲线类型：

```swift
enum BrightnessCurve: Codable {
    case identity
    case linear
    case power(gamma: Double)
    case piecewiseLinear(points: [CalibrationPoint])
    case monotonicCubic(points: [CalibrationPoint])
}
```

参考点：

```swift
struct CalibrationPoint: Codable, Identifiable {
    let id: UUID
    var referenceValue: Double   // x, 0...1
    var targetValue: Double      // y, 0...1
    var note: String?
    var createdAt: Date
}
```

所有值在进入模型时都要经过 `clamp(0, 1)`。保存前必须排序、去重并执行单调性检查。

### 4.3 存储位置

优先使用 `UserDefaults(suiteName: Bundle.main.bundleIdentifier)` 中的一个版本化键，例如：

```text
brightnessMappingProfiles.v1
```

写入策略：

1. 先把完整对象编码成 Data。
2. 在内存中验证 JSON/PropertyList 可解码。
3. 一次性写入 UserDefaults。
4. 写入失败时保留旧配置并提示用户。
5. `AppDelegate.settingsReset()` 时删除曲线配置并回到所有显示器线性模式。

如果以后配置体积增大，再迁移到应用支持目录中的 JSON；首版不提前引入文件锁和复杂数据库。

## 5. 曲线与拟合策略

### 5.1 统一数学约定

所有曲线均为前向映射：

```text
目标显示器亮度 = f(参考 Mac 亮度)
```

输入、输出均在 `0...1`。任何曲线求值都必须：

1. 检查输入是否有限。
2. 将输入裁剪到 `0...1`。
3. 求值。
4. 将输出裁剪到 `0...1`。
5. 对异常值回退到线性曲线。

### 5.2 默认直线

无参考点时使用：

```text
f(x) = x
```

这保证新版本不会因为没有校准数据而改变现有亮度范围。

### 5.3 分段线性

适合作为首个可交付拟合函数：

- 至少需要两个点；如果用户没有输入端点，自动补 `(0, 0)` 和 `(1, 1)`。
- 相邻点之间使用线性插值。
- 超出点范围时使用端点值或端点切线，首版优先使用端点值，避免过冲。
- 点必须按 `x` 严格递增。
- `y` 不强制严格递增，但默认禁止明显反向，防止滑块方向和视觉感受相反。

### 5.4 单调三次插值

当用户记录了四个或更多点时，可以提供单调三次 Hermite 插值：

- 保证曲线经过所有参考点。
- 保持单调，避免普通三次样条在点之间产生波峰和负值。
- 需要实现或引入经过许可确认的纯 Swift 数学实现；不能直接使用未经确认的第三方库。
- 点数不足时自动降级为分段线性。

### 5.5 幂函数/Gamma 函数

提供一个低参数量选项：

```text
f(x) = x ^ gamma
```

- `gamma = 1` 是直线。
- 建议初始范围限制在 `0.25...4.0`。
- 通过单个滑块或数值输入调节。
- 如果用户已有参考点，可用最小二乘估计初始 gamma，再允许手工微调。

### 5.6 不建议首版提供的函数

- 三次/四次无约束多项式：容易过冲，端点附近可能反向。
- 任意用户脚本：会增加安全、兼容和配置迁移成本。
- 每台显示器独立的非单调曲线：会让亮度滑块方向与用户预期相反。

### 5.7 拟合质量指标

窗口中可以显示，但不把它当成物理准确度：

- 最大绝对误差：`max(|predictedY - measuredY|)`。
- 均方根误差：`sqrt(mean(error^2))`。
- 单调性状态。
- 是否有端点补点。
- 是否发生裁剪。

这些指标只衡量曲线对用户输入点的贴合程度，不代表真实光学亮度误差。

## 6. 预览、保存和取消

### 6.1 事务状态

打开窗口时创建一个编辑事务：

```text
originalProfile   // 打开窗口时的已保存配置
workingProfile    // 用户当前编辑的配置
originalBrightness[displayID]
previewBrightness[displayID]
```

所有滑块操作只更新 `workingProfile` 和预览值，不直接写入永久配置。

### 6.2 预览规则

- 预览开启时，可以临时调用 `setDirectBrightness(_:transient: true)`。
- 预览更新要节流，建议 30 到 60 毫秒合并一次，避免持续拖动时密集发送 DDC。
- 预览期间暂停等亮度自动同步，避免校准滑块和后台 `job()` 互相抢写。
- 保存、取消、窗口关闭和显示器重新配置都必须结束预览事务。

### 6.3 保存

点击“保存”时：

1. 验证所有曲线和参考点。
2. 将工作配置编码并原子写入。
3. 更新运行时映射缓存。
4. 恢复正常亮度同步。
5. 将当前预览亮度作为新的运行时状态，不重复造成跳变。
6. 记录配置版本和更新时间。

### 6.4 取消

点击“取消”或关闭窗口：

1. 丢弃 `workingProfile`。
2. 将所有参与预览的显示器恢复到 `originalBrightness`。
3. 不写入 UserDefaults。
4. 不改变现有 `enableBrightnessSync` 开关。

若恢复某台显示器失败，应在窗口中报告失败的显示器，并继续恢复其他显示器。

## 7. 与现有同步循环的集成

### 7.1 新增映射服务

建议新增一个无 UI 的服务层，例如：

```text
BrightnessMappingStore
BrightnessCurveEvaluator
BrightnessSyncCoordinator
```

职责分离：

- `BrightnessMappingStore`：读取、校验、保存和迁移配置。
- `BrightnessCurveEvaluator`：只负责曲线求值和拟合，不访问显示器。
- `BrightnessSyncCoordinator`：选择参考源、应用目标值、处理节流和反馈保护。

### 7.2 目标值计算

映射模式启用且参考源为 Mac 显示器时：

```text
referenceValue = referenceDisplay.getBrightness()
for target in displays where target != referenceDisplay:
    targetValue = curve[target.identity].evaluate(referenceValue)
    target.setBrightness(targetValue)
```

现有线性模式保持：

```text
targetValue = target.getBrightness() + delta
```

首版不直接删除旧代码，而是在同步层按配置选择路径。

### 7.3 参考源选择

默认策略：

1. 优先使用内置显示器。
2. 没有内置显示器时使用 Apple 显示器。
3. 如果有多个候选，使用配置中保存的 reference identity。
4. 找不到参考源时暂时回退到现有线性增量同步。

外接显示器自身被用户手动改变时，首版不把变化反向推给 Mac，避免形成闭环。后续如需双向同步，再增加明确的“外接显示器也可作为参考源”策略。

### 7.4 防止反馈循环

曲线同步会触发目标显示器状态变化，必须避免目标变化再次成为新的参考输入：

- 记录同步事务 ID、源显示器身份和目标显示器身份。
- 对正在写入的目标设置短期抑制窗口。
- `refreshBrightness()` 发现变化时先判断是否为本程序刚刚写入的值。
- 平滑过渡期间不启动新的参考源变化传播。
- 只在主线程/指定串行队列中更新映射状态，DDC 写入仍遵守现有队列。

### 7.5 与平滑过渡的关系

曲线计算应得到最终目标值，平滑过渡仍由现有 `setBrightness()` 负责。不能对每一个中间动画帧重复拟合，否则会造成曲线误差累积。

当用户关闭“平滑亮度转换”时，映射仍然有效，只是目标显示器直接跳到曲线计算出的值。

## 8. 异常和边界情况

### 8.1 显示器拔插

- 配置按稳定身份保存，不因当前 `CGDirectDisplayID` 改变而丢失。
- 显示器消失时保留配置但标记为离线。
- 重新接入且身份匹配时自动恢复。
- 同型号无序列号的多台显示器需要在列表中提示用户手工确认，不能静默套用错误曲线。

### 8.2 DDC 不可用

- 显示器仍可显示曲线，但“预览”和“写入”按钮显示不可用原因。
- 不因为一次 DDC 读失败就删除曲线。
- 写入失败时保留配置，恢复旧亮度并提示具体显示器。

### 8.3 组合硬件/软件调光

曲线输入输出都使用 `Display` 的归一化值，不能把 DDC 0 到 100 直接当作曲线坐标。这样可以复用现有的组合调光切换点和软件亮度逻辑。

### 8.4 虚拟显示器和 Sidecar

首版可以允许配置，但默认不把虚拟显示器作为参考源。若无法稳定恢复 Gamma/shade 状态，预览失败时必须自动回滚。

### 8.5 HDR、True Tone、Night Shift 和环境光

这些因素可能在不改变亮度控制值的情况下改变观感。窗口应在首次校准时显示简短提示：

- 尽量固定 True Tone、Night Shift 和环境光状态。
- 在主要使用环境下校准。
- 更换色彩模式、HDR 状态或显示器预设后可能需要重新校准。

## 10. 测试计划

### 10.1 曲线计算单元测试

覆盖：

- 直线 `f(x)=x` 在 0、0.5、1 的结果。
- 分段线性插值和端点补齐。
- 输入小于 0、大于 1、NaN、无穷值时的裁剪和回退。
- 点乱序、重复 `x`、反向 `y` 的校验。
- 幂函数 gamma 边界。
- 单调三次插值不产生越界和反向。
- 曲线版本迁移失败时回退到线性。

### 10.2 配置存储测试

- 保存后重新启动可以读取相同点和曲线类型。
- 取消编辑不会改变持久化数据。
- 重置设置会删除曲线并恢复默认直线。
- 显示器拔插后使用稳定身份恢复。
- 无法解码旧数据时保留默认配置，不阻塞应用启动。

### 10.3 UI 测试

- 通用设置中按钮在中文和英文下可见，和“重置设置”样式一致。
- 窗口可以打开、调整大小、关闭。
- 添加、编辑、删除参考点后图和列表同步。
- 保存和取消行为符合事务规则。
- 没有两台显示器时显示明确提示。
- 预览后取消能恢复所有显示器原始亮度。

### 10.4 实机验证矩阵

至少验证：

1. MacBook 内置屏幕 + 一台 DDC 显示器。
2. MacBook 内置屏幕 + 两台不同品牌 DDC 显示器。
3. Apple 外接显示器作为参考源。
4. 仅软件调光的虚拟/不支持 DDC 显示器。
5. 开启和关闭平滑亮度转换。
6. 开启和关闭组合硬件/软件调光。
7. 睡眠、唤醒、显示器拔插后曲线仍能恢复。
8. 同步开关关闭时不产生任何自动写入。

验证时同时记录：

- 参考屏幕的控制值。
- 每台目标屏幕的控制值。
- 曲线计算出的目标值。
- 实际写入是否成功。
- 是否出现反馈循环或反复跳动。

不能仅凭“窗口打开”或“按钮显示”认定等亮度功能有效；必须在真实显示器上观察并记录映射后的亮度变化。

## 12. 验收标准

### 入口验收

- 通用设置中红框位置出现“等亮度设置”。
- 按钮颜色、圆角、边框和字体与橙色框中的“重置设置”一致。
- 中文显示“等亮度设置”，英文显示“Equal Brightness Settings”。
- 窗口宽度变化和语言切换不会遮挡同步复选框。

### 弹窗验收

- 可以打开、保存、取消和恢复默认。
- 网格、Mac 直线、其他显示器曲线和图例都清晰可辨。
- 添加参考点后曲线立即更新，点可以编辑和删除。
- 取消不会留下预览亮度或配置副作用。

### 运行时验收

- 默认线性曲线不会改变旧功能的亮度范围。
- 曲线模式下，调节 Mac 参考亮度时每台显示器使用自己的映射值。
- 目标值始终在 `0...1`，不会越界或反向跳变。
- DDC 写入失败、显示器拔出、睡眠唤醒时可以安全回退。
- 日志能区分“旧线性同步”和“曲线映射同步”。

## 13. 默认决策汇总

为减少后续反复讨论，首版按以下默认值设计：

- 参考屏幕：Mac 内置屏幕优先。
- 初始曲线：所有显示器都是 `y=x`。
- 首个拟合函数：分段线性。
- 参考点：至少三个亮度区间，允许更多点。
- 过冲处理：禁止，输出裁剪到 `0...1`。
- 预览：默认开启，但只在弹窗打开期间生效。
- 保存：原子保存整个版本化配置。
- 取消：完整恢复打开窗口前的亮度。
- 同步接入：新增曲线模式，旧线性模式保留为回退。
- 新功能默认开关：首版默认关闭，实机验证通过后再决定是否改变默认值。
